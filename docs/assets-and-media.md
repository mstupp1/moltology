# Assets and media

Read this before adding or changing media, asset URLs, or upload workflows.

- Finished social posts, carousel slides, reels and shorts are archived in Google Drive under `My Drive/Projects/Moltology/Social Archive/`, with direct local media uploads to Zernio through the social CLIs. `SOCIAL_ARCHIVE_ROOT` overrides the existing Moltology folder. Archive writes precede queueing; preserve final files after failures. See [`docs/social-archive.md`](social-archive.md). Website/blog media, character source assets and reusable templates remain on Neon S3.
- Heavy website media (content images, textures, video, audio) lives in the Neon S3 bucket `moltology-public-assets`, never in `public/`. Resolve URLs with `getAssetUrl(path)` from [`src/lib/assets.ts`](../src/lib/assets.ts). Pages load bucket media through `/media/*`, a CDN-cached rewrite in `vercel.json`, because direct bucket reads count against Neon's 5 GB monthly transfer that the database shares. Never point a page, CSS file, or og:image at the bucket URL; use `getAssetUrl` (or `getAbsoluteAssetUrl` for emails and og:image). Every upload path (`npm run s3:upload`, blog ingest, `npm run s3:sync`) writes a compressed `.webp` twin (max 1920px) for jpg/png under `images/` except `images/social/`; `getAssetUrl` serves the twin and `getAbsoluteAssetUrl` the original. Reference the original key in code and content. `npm run s3:optimize -- --check` lists images missing a twin. `npm run s3:sync` uploads and `npm run s3:verify` checks parity.
- Link previews (og:image): pages without their own picture show the site card, `public/images/sharing/site-card-v1.jpg`. Member profile links show a card drawn by `/api/share/member/v2/<portrait>.jpg` from the member's saved 3D portrait (the 512px copy when there is one), or the crab card `member-card-v2.jpg` when they have none. Both are small brand images kept in `public/` like the emblem, and stay under 300KB so WhatsApp shows them. `npm run share:cards` redraws all the artwork from [`scripts/build-share-cards.ts`](../scripts/build-share-cards.ts); bump `SHARE_CARD_VERSION` in `src/lib/share-card.ts` when the member card changes.
- `npm run assets:check` (run in CI by `.github/workflows/hygiene.yml`) blocks any tracked file over 1MB unless it is allowlisted in `scripts/check-asset-budget.ts`.
